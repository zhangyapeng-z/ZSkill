## 5. 部署步骤

### 5.1 裸机部署
```bash
# 1. 上传 JAR
scp {jar文件} user@server:/opt/app/

# 2. 创建配置目录
mkdir -p /opt/app/config

# 3. 启动服务
nohup java -jar /opt/app/{jar文件} \
  --spring.profiles.active=prod \
  --spring.config.location=/opt/app/config/ \
  > /opt/app/logs/app.log 2>&1 &
```

### 5.2 Docker 部署
```bash
# 构建镜像
docker build -t {镜像名}:{版本} .

# 运行容器
docker run -d \
  --name {容器名} \
  -p {端口}:{端口} \
  -e SPRING_PROFILES_ACTIVE=prod \
  -v /opt/app/config:/app/config \
  {镜像名}:{版本}
```

### 5.3 Kubernetes 部署
{如有 Helm Chart 或 K8s manifests}
```bash
# 使用 Helm 部署
helm install {release-name} charts/{chart-name} \
  --set image.tag={版本} \
  --set profile=prod

# 或使用 kubectl
kubectl apply -f k8s/
```

## 6. 健康检查

### 6.1 应用健康检查
- **Liveness**: `GET /actuator/health/liveness`
- **Readiness**: `GET /actuator/health/readiness`
- **完整健康**: `GET /actuator/health`

### 6.2 K8s 健康检查配置
```yaml
livenessProbe:
  httpGet:
    path: /actuator/health/liveness
    port: {端口}
  initialDelaySeconds: 60
  periodSeconds: 30

readinessProbe:
  httpGet:
    path: /actuator/health/readiness
    port: {端口}
  initialDelaySeconds: 30
  periodSeconds: 10
```

### 6.3 监控指标
- Prometheus: `/actuator/prometheus`
- 日志采集: {ELK/Loki 配置}

## 7. 回滚策略

### 7.1 裸机回滚
```bash
# 1. 停止当前版本
kill $(cat /opt/app/app.pid)

# 2. 替换 JAR
cp /opt/app/backup/{old-version}.jar /opt/app/app.jar

# 3. 重启
nohup java -jar /opt/app/app.jar --spring.profiles.active=prod &
```

### 7.2 Docker 回滚
```bash
docker stop {容器名}
docker run -d --name {容器名} {镜像名}:{旧版本}
```

### 7.3 K8s 回滚
```bash
# 查看部署历史
kubectl rollout history deployment/{deployment-name}

# 回滚到上一版本
kubectl rollout undo deployment/{deployment-name}

# 回滚到指定版本
kubectl rollout undo deployment/{deployment-name} --to-revision={N}
```

### 7.4 数据库回滚
{如有 Flyway/Liquibase，给出回滚命令}
```

## Template Usage Notes

- `{占位符}` 中的内容由扫描脚本产出的 JSON 数据填充
- 表格行通过遍历 JSON 数组自动生成
- Mermaid 图从 `dependency-topology.mmd` 文件嵌入
- 模板中的配置项需根据实际检测到的技术栈动态调整
- 如某模块/中间件未检测到，对应小节标注 "N/A" 或省略
