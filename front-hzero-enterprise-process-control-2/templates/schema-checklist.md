# Frontend Schema Checklist

用途：在前端阶段结果、Handoff 和 Lite 并行汇合前，快速核对 `frontend-stage-result` 与 `task-status.md` 的字段完整性、一致性和降级状态。本文是运行时字段检查模板，不是业务交付产物；除非流程要求留痕，否则不需要写入 feature workspace。

字段准入、核心/条件/信息字段分层、consumer 责任和豁免边界见 `references/frontend-stage-result-field-governance.md`。字段进入本模板前必须已有 owner、consumer、值域和 stage contract 校验边界。
并发一致性、placement、runtime/compliance 和最终汇合判定的长规则见 `references/schema-runtime-gates.md`。本模板只保留检查入口、关键闭合条件和回退动作。
route、field、style、component/type/provenance 等字段级 contract 的长规则见 `references/schema-field-contract-gates.md`。本模板只保留字段名、最小值域和异常回退动作。

## 使用位置

- `frontend-auto-agent` 输出最终 `frontend-stage-result` 前。
- `frontend-artifact-agent` 生成 `frontend-stage-result-fields` 和 Handoff 前。
- `hzero-auto-agent-lite` 执行并行汇合前。
- Review / Verify / Implementation 发现 task 状态映射异常时。

## 字段分层

- Core Merge Fields：固定为 15 个直接汇合字段；question、路径、trace、mock、replacement 和专项合同均按条件字段处理，普通汇合不得预展开。
- Conditional Contract Fields：只在命中特定 gate 或页面模式时 required，例如 `contracts.realApiCandidateBranch`、`contracts.actionServiceSwitchPolicy`、`uiContracts.masterDetailModeContract`、`contracts.attachmentContractCarrier`、`contracts.placeholderRequestPathPolicy`。允许不是每个 consumer 都逐项直读，但必须在 owning stage、manifest、replacement 或 checklist 中有机械约束。
- Informational Or Trace Fields：主要用于 Design closeout、阶段追溯、恢复上下文或解释来源，例如 `designState.frontendDesignState`、`designState.closeoutLoopResult`、`designState.designCumulativeFallbackPolicy`、`designState.designUnderstandingDeviationCheck`。不应无约束升级成 merge 决策字段。

## Frontend Stage Result Checklist

本节只登记 `frontend-stage-result` 顶层字段。单阶段、单专项或只服务恢复/审计的细字段必须折叠进对象字段；旧顶层细字段不得继续作为新产物输出。

## 汇合判定

| 目标状态 | 必须满足 |
| --- | --- |
| `production-ready` | 细则见 `references/schema-runtime-gates.md`；至少核对 question gate、contract、review、verification、write scope、targetPlacement、baselineComparison、`productionCompliance`、`complianceManifest`、`blockers` 和 replacement 均已闭合；任一核心 gate 不闭合则不得 production-ready |
| `conditional` | 细则见 `references/schema-runtime-gates.md`；存在可演示目标、mock/demo 实现、未闭合验证项或条件性交付风险时使用。必须写 `buildable/reachable/usable`、未验证项、`manualVerificationRequired`、前端服务提示、状态分组和 `done=false`；`done=false` 表示不能 production-ready / 主流程闭环 DONE，不表示前端代码实现失败；默认 mock/demo 仅缺外部页面运行态证据时不需要额外用户确认；不得写 DONE / production-ready |
| 非 canonical 交付状态 | `code-only`、legacy demo label、顶层 `non-runnable` 等一律 `invalid-stage-result`，回原 owning stage 重新生成结果，不得转换后继续 |
| `blocked` | 只用于 `terminalBlockClass=core-contract-unresolvable / non-runnable-target / write-scope-or-dirty-conflict / external-permission-unavailable / user-decision-required`。required 内部证据、调用参数、task-status、owner capsule、汇总字段、repair budget 或 timebox 缺口必须先在同一前端子流程闭合；demo-slice 外部 runtime 证据、production-only 参数和允许 not-run/unknown/pending 的事实进入 conditional |
