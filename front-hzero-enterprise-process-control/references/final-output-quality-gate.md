# 最终输出质量门禁

用途：约束 Verification、Handoff、frontend-stage-result 汇总和 Lite 最终回复，避免交付结论中出现无意义字符、乱码、错别字、重复字或未解释残留词。

## 适用范围
- 用户可见的最终回复、阶段汇总、验证结论、Handoff 摘要和 frontend-stage-result 摘要。
- 命令验证、构建结果、页面运行态验收、Review/Handoff 结论。
- 不替代代码、设计或验证事实门禁；只约束输出文本质量和验证结论表达。

## 发送前自检
最终回复发送前必须执行输出自检：
- 检查最后一句、验证结论句、命令摘要句和下一步句。
- 删除无意义词、乱码、错别字、重复字、半截命令、未解释的拼音/中文词、孤立符号和残留字符。
- 不在验证结论后追加口语化尾巴或自由补全词。
- 若发现无法解释的词，例如误生成的两个汉字、半截命令或多余 token，必须删除后再输出。

## 验证结论固定格式
用户可见验证结论必须使用固定句式之一：
- `验证：<command>，passed。`
- `验证：<command>，failed，错误为 <summary>。`
- `验证：<command>，not-run，原因是 <reason>。`
- 多命令时使用矩阵或逐行列出，每行保持 `命令 / 结果 / 证据或原因`，不得把候选命令写成已运行。

示例：
- `验证：npm run build:ms -- <module>，passed。`
- `验证：npm run build:ms -- <module>，failed，错误为 TypeScript 编译失败。`
- `验证：未运行 build，not-run，原因是用户要求先不执行构建。`

HZEROJS Umi 子模块最终编译固定使用 `npm run build:ms -- <module>`。`--` 是 npm 参数分隔符；不得把用户可见验证句改成 yarn、pnpm 或其它 build 命令。未运行时必须写明 `not-run` 原因，根 scripts 缺少 `build:ms` 时使用 `missing-required-build-ms-script`。

## 命令输出与助手总结边界
- 真实命令输出必须标为 `命令输出：` 或放入验证报告证据，不得把助手误生成文本当作命令输出。
- 助手概括必须标为 `结论：`、`验证：`、`风险：` 或 `下一步：`。
- 若命令输出中确有异常字符，必须说明它来自命令原始输出；否则视为输出噪声并删除。

## 交付回复结构
重要交付回复优先使用以下短结构：
1. `变更：`
2. `验证：`
3. `风险：`
4. `下一步：`

简单任务至少保留 `完成内容 + 验证`。验证句后不得追加无关文本。

## Review / Handoff 判定
- 出现无意义字符、乱码、错别字、重复字或未解释残留词时，输出质量门禁为 failed。
- failed 时不得把 Handoff 或最终回复视为 clean；必须修正文案后再交付。
- 该门禁不改变验证事实，但会阻止“已交付摘要无问题”的判断。
