# Generated Code Static Quality Gate

用于 Implementation 自查、Review 前置审查和用户手测问题回灌时，拦截“代码能生成但不符合企业前端资产要求”的常见漏网项。它不替代 UI Contract、场景 SOP 或 Choerodon 静态清单；只聚合跨场景、可检索、应一票否决或至少形成 finding 的生成代码质量门禁。

## 阅读路由
- 先读 `Scope` 和 `Required Static Search` 判断是否必须扫描。
- 命中关键词后读 `Blocking / Major Rules` 对应条目，不要仅凭关键词报错。
- 导入导出、行操作、附件和 HZERO 通用组件命中时，分别回到 `front-hzero-import-export`、`front-hzero-choerodon-ui` 的 row-actions scenario reference、`front-hzero-attachment`、`front-hzero-common-components` 做正向证明。
- 输出 finding 时按 `Output Requirement` 填写字段。

## 主题索引
- `Task Acceptance Scan`：任务验收段落、`mustPassBeforeMockCompleted`、流程产物落点、实现自查回写。
- `ID / field / display semantics`：ID runtime、field usage、labelSource、field visibility、empty/derived field UX、LOV/lookup、只读展示语义。
- `Request / mock / adapter`：production transport、mock-request、servicePrefix、runtime store、data entry drift、fake resource path、mock-to-production switch。
- `UI / layout / interaction`：action entry、button placement、status action guard、style necessity、detail title 辅助展示、滚动与 HZERO page layout。
- `Component / renderer / permission / i18n`：componentApi、renderer helper、权限按钮、wrapper/i18n、HZERO common components、导入导出 wrapper。
- `Submodule / route / dependency`：submodule skeleton、active registry、current-tab / dynamic-tab、route system、dependency drift。

## Owner Map
- Task 字段面和任务模板来源：`templates/task-breakdown.md`
- UI Contract / Route Context / Button Semantic / Action Entry：`frontend-ui-runtime-gates.md` 与 Design 期 `frontend-ui-contract-guardrails.md`
- Production compliance 字段面：`frontend-compliance-manifest.md`、`frontend-compliance-manifest-governance.md`
- Submodule / Target Placement：`hzerojs-submodule-runtime-gate.md`、`schema-runtime-gates.md`
- ID runtime：`frontend-id-runtime-contract.md`

本文件只聚合跨场景静态质量阻塞项和 finding 口径；不要把这里再转抄回 agent/template。agent/template 只应引用主题、gateId、owner reference 和当前 feature 命中的 blocked reason。

## 引用方式
- 输出 finding 时优先引用本文件稳定 `GCSQ-*` gateId；若条目内已经有更细的 `HZC-*` 生产合规编号，可在 `assetRule` 或补充证据中一起带出。
- agent/template 只需要写：`gateId + owner reference + 当前命中的 blocked reason`，不要复制整段规则正文。
- 同一问题若同时触发 UI/runtime 和静态质量门禁，优先双引：例如 `gateId=HZUI-ROUTE-001 + GCSQ-ROUTE-002`。

## Scope

命中以下任一条件时必须执行：

- 新增或改造 HZERO + Choerodon 页面、DataSet、service、mock/demo 或 production transport。
- 代码来自自动生成、demo-slice、mock-demo 或 Review/手测返工。
- 用户要求评估生成代码是否符合企业前端资产要求。

## Blocking / Major Rules

- **Task Acceptance Scan (`GCSQ-TASK-001`)**：Implementation 回写 `task-status.md` 前必须对本轮触达 task 的 `Implementation Requirements`、`Contract Acceptance`、`UI Acceptance`、`Verification Acceptance`、`Rejection Criteria`、`mustPassBeforeMockCompleted` 和 `staticRejectionScan` 形成结果。若任务拒收条件未扫描或未通过，不得进入 `mock-completed / usable=true / Implementation Complete / Done`，只能返回 `partial-needs-rework / blocked-needs-rework / blocked`。一票否决信号包括：手写查询 Form 替代 DataSet queryFields、FDS/TDS/UI Contract 要求搜索框/关键字/模糊查询但实现缺顶部 fuzzy search、显式 `queryBarProps.fuzzyQuery=false`，把 UI Contract 字段映射误写成 `queryBarProps.fuzzyQueryField/fuzzyQueryFields`，或在 `queryBarProps` 中生成无 Choerodon typed surface / 项目 wrapper 证据的自造 key、可见区域未继承 `expectedSurface / forbiddenSurface / requiredVisibleByDefault` 或实现落到 `forbiddenSurface`、主数据字段以普通 TextField 落地、附件字段以 TextField/Output raw UUID 落地、required 导入导出以普通 Button/disabled/no-op/提示入口落地、create/edit 表单预填无来源示例业务值、mock handler 的 `demoGeneratedValue` 反向污染 create/edit 默认业务输入或 submit payload、create 未保存态显示审计/后端生成字段空 `Output` 或把 displayOnly 审计字段带入 submit payload、create 未保存态显示无来源的编号/合计/比例只读空字段、目标源码目录写入 `__implementation-self-check__.md`、local-filter 或组件内数组冒充 mock-request、父工程托管子模块缺 `parentMockPluginRegistrationEvidence`、`mockPluginTemplateCompliance` 非模板合规、`mockPluginSelfCheck=failed/not-run`、mock plugin 出现 `api.app` 直接挂载、`mockPrefixOriginPolicy` 不是 `current-dev-server-origin`。若实现摘要或 self-check 自述“demo 降级 / TextField 附件 / disabled 导入导出 / 生产需替换”，且对应能力是任务 required，该自述是失败证据，不是可接受 partial 证明。
- **ID runtime**：只做静态扫描入口和 finding 聚合，规则源以 `frontend-id-runtime-contract.md` 为准。命中 `*Id/*Ids` 的 `number/number[]`、`Number()`、`parseInt()` 或一元 `+` 时，按该规则判定严重级别，不在本文重复扩展口径。
- **Mock / production request boundary (`GCSQ-REQ-001`)**：production transport 必须使用已确认 HZERO/project request helper。`fetch/axios/XMLHttpRequest` 在 `queryMode=mock-request` 且请求 HZERO 本地 devServer mock API 时允许使用，但必须标明 mock-only 边界、内置 devServer middleware/plugin 链路字段和 production replacement；不得因此声明 production-ready。硬编码 `http://localhost:*` 或绝对 mock URL 只能作为明确本地 devServer mock API 证据使用；缺少 queryMode、内置 mock plugin 注册计划或 replacement 说明时，按 mock 边界缺失处理，不得 usable=true，不要表述为“生产请求契约已闭合”。只有 production transport 或未声明 mock/request 边界时，未确认 native-http 的 `fetch/axios/XMLHttpRequest` 才按 major/blocking 处理。
- **HZERO mock adapter boundary (`GCSQ-MOCK-001`)**：新生成 mock-request 默认不得读取 `_smock`、`smock`、`sproxy` 或历史 `*.mock.js`；这些目录/文件只能作为存在性 legacy signal。只有用户明确要求 legacy mock 迁移、审计或解释时才允许只读，并必须标记 `legacyMockEvidenceOnly=true`；读取结果不得作为字段来源、seed、主接入点或交付方案。mock/demo 请求必须使用隔离命名空间 `/_mock/<module>/v1/{organizationId}/...`，并保证 service/DataSet baseUrl 与 middleware 监听 path 同源同路径；`servicePrefix.ts` / buildUrl helper 的 mock 分支必须返回当前 dev server origin + `/_mock/<module>`，不得只返回裸 `/_mock/<module>` 后交给 HZERO/project request。`<unconfirmed-gateway-prefix>/...` 默认是真实网关/后端入口，不得作为新生成 mock/demo 前缀；`/api/v1/demo-org`、裸 `/api/v1`、硬编码 `demo-org`、`/_smock`、`/mock`、`/_local` 等至少 major，同时声明 usable=true、裸 `/_mock` 被拼到远端 `API_HOST` 或 Network 落到远端 `API_HOST` 时 blocking。若裸 `/_mock` 可能被 request helper 拼到远端 `API_HOST`，必须使用隔离的 dev-only current-origin mock HTTP adapter；不得改全局 request、不得回退到 `<unconfirmed-gateway-prefix>` 伪装 mock。Target Placement 是父工程托管子模块时，mock plugin/handler/data/store 应归属与 `config` 平级的子模块 `dev-mock` 目录，不存在时新建；旧 `config/<module>-dev-mock*.js` 位置无效。默认命名为 `dev-mock/<module>-dev-mock-plugin.js` 和 `dev-mock/<module>-dev-mock.js`，handler 必须直接导出 middleware 函数，plugin 必须来自 `templates/submodule-dev-mock-plugin.js.template` 的占位符替换结果，直接 require handler 并使用 `api.addBeforeMiddlewares(() => [middleware])` 注册，不得生成旧 `api.addBeforeMiddleware` fallback；模板生成物必须保留启动自检：导出类型校验、`__mockMount` 与 `/_mock/<module>/` 一致性校验、重复注册跳过/告警、注册日志和缺失 Umi 扩展点的明确错误；POST/PUT/DELETE body 读取使用 mock 模块内 `readJsonBody` 或项目已有 parser；数据量较多、包含多接口 seed、状态流转或头行明细 store 时拆为 `dev-mock/<module>-dev-mock-data.js`、`dev-mock/<module>-dev-mock-store.js` 或等价小模块，只有 1-2 条简单 seed 时允许内联；拆分后 handler 必须显式 require/import data/store，并让列表、详情、动作和刷新接口从同一 data/store 读取或写回，未接线至少 major，导致空数据或仍声明 usable=true 时 blocking。mock response shape 必须先按 `GCSQ-MOCK-005` 对账 DataSet/service 消费端；只有消费端明确需要 page-response 时，分页 mock 才返回 `content / totalElements / size / number`，并按 0-based `page/size` 计算 `start = page * size`，缺省 page 必须是 0；使用 `(page - - **DataSet read / adapter activation (`GCSQ-ADAPTER-001`)**：`transformResponse` 不是必选项；若 raw response shape 已被 DataSet `dataKey/totalKey` 或项目 request adapter 正确消费，可以不写 `transformResponse`。必须保证 DataSet `transport.read` 成功路径有且只有一条可解释的数据归一化链路：raw shape + `dataKey/totalKey`、`transformResponse`、response adapter 或项目 helper。确需生成 `transformResponse` 时，返回值必须是当前 DataSet/request adapter 可直接消费的对象或数组；除非项目 request adapter 有明确源码证据要求字符串，否则不得把已解析对象重新 `JSON.stringify`，不得为了兼容多种分页命名而覆盖或破坏原有 `content/totalElements` 等已对齐字段。DataSet `transport.read/create/update/destroy/submit` 默认必须返回 DataSet 可消费的 request config，不得 import 或调用业务 service 函数返回 Promise 数据；`transport.read: ({ params }) => queryRequisitionLines(requisitionHeaderId, params)`、`transport.submit: () => saveXxx(...)`、`url: '/_local/...' + transformResponse 调业务 service/loadData` 是明确拒收形态。相似页面中的 DataSet 调 service 写法只能作为 legacy signal，不得作为新代码默认范式。关键 adapter 只停留在注释中且无等价成功路径、导入 helper 未被调用、queryParameter 不参与过滤/详情加载，至少 major；导致详情/明细/列表读错数据时 blocking。单记录详情/头详情/不分页明细如果返回普通对象或数组，应显式 `paging: false`，或通过 `dataKey/totalKey` / `transformResponse` / response adapter 映射为 DataSet 可消费结构；`pageSize: -1` 不是关闭分页。分页模式下 mock/API 返回普通对象、数组、`list/rows/content` 未映射到 `dataKey`、或缺 `total/totalElements` 等 totalKey，导致接口有数据但 Form/Table 不显示，至少 major；仍声明 usable=true/production-ready 时 blocking。详情明细无数据排障必须先确认行 DataSet read 已触发；若没有 Network/query 证据，先按 `HZC-LINE-DATASET-ACTIVATION-001` 修查询激活，不得只扩大 `transformResponse` 兼容范围后声明完成。若存在 `ensureRuntimeSeedsLoaded`、runtime store 或 mock service，但 DataSet read 成功路径不读取同一 store，只在保存/删除/提交等 action 函数中使用 store，应按 mock runtime store dead path / disconnected store 判定，至少 major；动作后刷新复现旧数据或详情/明细读取不同源时 blocking。
- **DataSet CRUD / field usage**：可编辑详情、主从、inline table 或流程页只有 `useEffect + service + loadData`，但缺生产 read/submit/create/update/destroy 契约时，按 `HZC-DATASET-CRUD-001` 形成 finding。任何 `record.get/set`、表格列、表单字段、查询字段或 actionGuard 使用未在 DataSet/API/fieldUsageMatrix 中声明的字段，按 `HZC-FIELD-USAGE-001`；状态 guard 字段缺失至少 major，导致按钮误放行时 blocking。
- **Choerodon Tabs TabPane import boundary (`HZC-TABS-TABPANE-IMPORT-001`)**：Choerodon Pro `TabPane` 不得从 `choerodon-ui/pro` 独立命名导入，也不得引用 `choerodon-ui/pro/lib/tab-pane`。正确模式是 `import { Tabs } from 'choerodon-ui/pro'` 后使用 `<Tabs.TabPane ...>`；若项目健康示例确认本地别名，可写 `const TabPane = Tabs.TabPane`，但必须在 Component Import Contract / `componentApiProvenance` 中记录 `Tabs.TabPane` 的 static-member 来源。`import { Tabs, TabPane } from 'choerodon-ui/pro'` 在按需构建中解析到缺失模块、详情 required 页签不可渲染或仍声明 usable=true/production-ready 时 blocking。
