# 隐私与脱敏规则

生成周报前**必须**过一遍脱敏检查，尤其是包含群聊消息、客诉记录、表格明细的数据。

## 默认脱敏字段（一律隐藏或脱敏，除非管理判断确需）

| 类别 | 字段 | 脱敏方式 |
|---|---|---|
| 客户 | 姓名 | 隐藏或"客户X" |
| 联系 | 电话、邮箱 | 打码，如 `138****1234`、`a***@example.com` |
| 地址 | 详细地址 | 只保留到城市/省份，删门牌 |
| 订单 | 订单号 | 打码或删 |
| 店铺 | 店铺账号、卖家 ID | 隐藏 |
| 密钥 | Token、密钥、密码、App Secret | **绝对删除** |
| 员工 | 敏感个人信息（薪资、身份证、健康等） | 隐藏 |
| 客诉 | 单条客诉隐私内容 | 只保留汇总，不保留个案细节 |

## 金额/订单/客户的展示规则

- 只有在**管理判断确实需要**时才使用。
- 优先**汇总展示**（总额、总数、趋势），不列单笔明细。

## 检查时机

在「编排流程第 ⑨ 步」执行，输出前自查：

1. 周报里是否出现了上述敏感字段的明文？
2. 是否有单条客诉/单个客户的隐私细节？
3. 是否引用了任何 token / 密钥 / App Secret？

> **任何 token 和密钥出现，一律删除后再输出。** 这是不可协商的红线，与 lark-unified 的"Never print appSecret or access tokens"一致。
