# 状态判定：事实 / 判断 / 待确认 与状态枚举

## 三级证据分类（每条关键事项必标其一）

| 级别 | 定义 | 示例 |
|---|---|---|
| **已核验事实** | 飞书材料明确记录，可直接引用 | "任务表状态=已完成，负责人=王元靖" |
| **综合判断** | 由多个来源归纳，非单一材料明示 | "会议纪要+任务共同显示 SOP 盘点已收尾" |
| **待确认** | 信息不足或来源冲突 | "会议写'准备启动'，任务写'已完成'" |

**禁止编造**：完成度、金额、业务效果、负责人、截止日期、项目状态、领导意见——凡飞书材料没写的一律不写，宁可标"信息不足"。

## 状态枚举（每个项目必判其一）

| 状态 | 判定依据 |
|---|---|
| 已完成 | 有明确完成证据（状态=完成 / 有结果产出 / 有验收记录） |
| 正常推进 | 有进行中的证据，且无风险信号 |
| 有风险 | 延期 / 阻塞 / 资源不足 / 依赖未到位 |
| 需决策 | 存在需领导拍板的分歧或选项 |
| 暂停 | 材料明确显示搁置或停止 |
| 信息不足 | 无法从现有材料判定 |

## 红线：进度措辞不得升级

| 材料原文 | 周报写法 |
|---|---|
| "计划完成" / "准备上线" / "正在讨论" | **仍写"进行中"**，不写"已完成" |
| "预计下周完成" | 写"进行中，预计下周完成" |
| "已完成"（有证据） | 才可写"已完成" |

## 状态冲突的判定顺序

1. 先按 `dedup-rules.md` 判断是否同一事项。
2. 同一事项多源状态不一致 → **不自行裁决**，标「状态冲突」。
3. 列出冲突来源（哪个会议/任务/表格各写了什么）。
4. 必要时向用户提出**一个具体确认问题**（例："会议纪要写该项目准备启动，但任务表显示已完成，周报应采用哪个状态？"），不泛泛问"还有什么补充"。

## 延期事项的处理

- 延期事项**必须说明影响**（影响谁、影响什么、影响多大）。
- 归入完整周报的「风险与判断」板块。
- 无影响证据时写"影响待评估"，不编造影响程度。
