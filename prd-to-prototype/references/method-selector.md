# 方法选择决策器

> 本文件为「需求PRD到产品原型」Skill 的方法选择引擎。模块一 Step1 场景诊断阶段读取，
> 根据七维场景诊断结果输出推荐方法组合。方法详细指引见 `method-toolkit.md`。

## 快速路径（满足条件时跳过决策矩阵）

收到需求后，**先执行快速路径判定**，满足全部条件则跳过下方§二决策树和§三决策矩阵，直接使用默认方法组合。

### 快速路径判定条件

| 条件 | 判定方式 | 理由 |
|------|---------|------|
| 成熟度 = L3 | 有完整功能清单+优先级+流程+非目标+验收期望 | 信息已充分，无需深挖 |
| D1 模糊度 = 明确 | 输入含具体功能清单、用户角色、流程描述 | 无需 5Whys/JTBD 深挖 |
| D2 需求量 = 少 | 功能点 ≤3 且聚焦单一功能 | 无需 Kano/RICE 全套排序 |

三条件**全部满足** → 进入快速路径，使用下方默认方法组合，跳过§二决策树和§三决策矩阵。
**任一不满足** → 进入正常路径，执行七维场景诊断+决策矩阵匹配。

### 快速路径默认方法组合

| 模块 | 默认方法 | 理由 |
|------|---------|------|
| 澄清 | M4 5W2H快速核查 + M16 MoSCoW | 信息已明确，只补缺口+分优先级 |
| PRD | M20 用户故事 + M29 Given-When-Then | 流程简单，标准格式即可 |
| 原型 | M37 高保真 + M47 走查清单 | 页面少，直接出高保真 |

### 快速路径流程

```
正常路径（5步）：成熟度初判 → 方法选择引擎 → 信息层核查 → 洞察层挖掘 → 矛盾检测 → MRC判断
                                                    ↓ 跳过
快速路径（3步）：成熟度初判 → 快速核查（5W2H 缺口补全，≤1轮） → MRC快速门禁（G1+G2+G4 三项即可）
```

### 快速路径推荐展示模板

```

你的需求满足快速路径条件：
```

### 中速路径（L2半成型+D1明确时触发）

收到需求后，若不满足快速路径（L3）但满足以下条件，走中速路径：

| 条件 | 判定方式 | 理由 |
|------|---------|------|
| 成熟度 = L2 | 有用户角色定义+功能清单（可能无优先级）+部分流程描述 | 信息较完整，只需补缺口 |
| D1 模糊度 = 明确 | 输入含具体功能清单、用户角色 | 无需 5Whys/JTBD 深挖 |

两条件**全部满足** → 使用中速路径默认方法组合，跳过决策树和决策矩阵。

### 中速路径默认方法组合

| 模块 | 默认方法 | 理由 |
|------|---------|------|
| 澄清 | M4 5W2H快速核查 + M16 MoSCoW | 补全缺口+分优先级 |
| PRD | M20 用户故事 + M29 Given-When-Then | 标准格式 |
| 原型 | M37 高保真 + M47 走查清单 | 直接出高保真 |

中速路径MRC简化为G1+G2+G3+G4四项（核心信息完整+P0可定义+主流程可走通+边界已划）。

## 一、七维场景诊断

### 1.1 诊断维度定义

| 维度 | 名称 | 取值 | 诊断方法（如何从用户输入判断） | 影响的方法选择 |
|------|------|------|------|------|
| D1 | **模糊度** | 模糊 / 明确 | 检查输入中是否包含具体功能清单、用户角色、流程描述。≤2句话且无功能拆解→模糊；有功能清单+流程→明确。复用现有成熟度分级：L0-L1=模糊，L2-L3=明确 | 模糊→5W2H+5Whys+JTBD；明确→直接进入排序/PRD |
| D2 | **需求量** | 多 / 少 | 统计用户提到的功能点数量。≥5个功能点或出现"要全做""都需要"→多；≤3个或聚焦单一功能→少 | 多→Kano+MoSCoW+RICE排序；少→直接定义P0进入PRD |
| D3 | **角色复杂度** | 单角色 / 多角色冲突 | 识别输入中提及的用户角色种类。仅1类用户→单角色；≥2类且有不同诉求（如"管理员审核"+"用户提交"）→多角色冲突 | 多角色→利益相关者地图+影响地图；单角色→同理心地图 |
| D4 | **流程复杂度** | 简单 / 复杂 | 判断是否有多步骤业务流程、状态流转对象（订单/工单/审批）、异常分支。有状态流转或多角色协作流程→复杂；单线性操作→简单 | 复杂→BPMN+状态机+决策表；简单→用户故事+验收标准 |
| D5 | **不确定性** | 低 / 高 | 判断是否为创新探索型需求（无市场验证、无竞品参考、方向未定）。有明确竞品/已有产品迭代→低；全新方向/无数据支撑→高 | 高→MVP+原型验证+可用性测试；低→标准PRD流程 |
| D6 | **端类型** | 移动 / PC / 多端 | 检查输入中提及的目标端。仅小程序/App/H5→移动；仅Web→PC；提及≥2端→多端 | 多端→设计系统+组件库+响应式；单端→标准原型 |
| D7 | **调研数据** | 有 / 无 | 检查用户是否提供了调研数据（访谈记录、问卷结果、竞品报告）。有→直接用5W2H+JTBD分析；无→建议先做调研 | 无→建议用户访谈+问卷+竞品分析（或标注假设）；有→直接消化数据 |

### 1.2 诊断执行方式

- 与成熟度初判（L0-L3）**合并执行**，不增加额外步骤
- 成熟度判定"追问深度"（轮数），场景诊断判定"用什么方法"（工具选择），两者正交
- 诊断流程：

```
用户输入需求
  → 解析需求文本/文档/图片
  → 同步执行：
      ├ 成熟度初判（L0-L3）         ← 现有能力，保留
      └ 七维场景诊断（D1-D7）       ← 新增
  → 输出：需求初判摘要 + 场景画像
  → 场景画像 → 决策矩阵匹配 → 推荐方法组合
  → 展示给用户确认
```

### 1.3 场景画像输出格式

诊断完成后，在"需求初判摘要"中追加场景画像块：

```
📊 需求场景画像

| 维度 | 判定 | 依据 |
|------|------|------|
| D1 模糊度 | 模糊 | 输入仅1句话，无功能拆解 |
| D2 需求量 | 少 | 仅提到1个核心功能 |
| D3 角色复杂度 | 单角色 | 仅提及C端用户 |
| D4 流程复杂度 | 简单 | 单线性操作，无状态流转 |
| D5 不确定性 | 高 | 全新方向，无竞品参考 |
| D6 端类型 | 移动 | 提及"微信小程序" |
| D7 调研数据 | 无 | 未提供调研材料 |

推荐方法组合：详见决策矩阵匹配结果（§三）
```

### 1.4 诊断维度与成熟度分级的关系

成熟度分级（L0-L3）回答"需求信息有多完整"，决定**追问深度和预计轮数**；七维场景诊断回答"需求场景有什么特征"，决定**用什么方法**。两者正交，合并执行不冲突：

| 体系 | 回答的问题 | 决定的内容 |
|------|-----------|-----------|
| 成熟度 L0-L3 | 需求信息有多完整？ | 追问深度、预计轮数 |
| 场景诊断 D1-D7 | 需求场景有什么特征？ | 澄清/PRD/原型各阶段用什么方法 |

### 3.2 多场景叠加规则

一个需求可能同时命中多个场景特征（如"多角色+复杂流程+B端"），此时按以下规则处理：

1. **取交集方法组合**：将多个命中场景的方法组合合并去重，而非只选一行
2. **优先级排序**：当方法组合冲突时，按"复杂度优先"原则——D4 > D3 > D2 > D1，高复杂度维度的方法优先
3. **用户可调**：推荐方法组合展示给用户后，用户可增删方法（如"跳过问卷，直接5W2H"）
4. **跨模块连贯**：澄清模块的产出方法决定PRD模块的输入方法（如澄清用了用户旅程地图→PRD用用户故事地图切版本）

### 3.3 动态调整规则

| 调整场景 | 处理方式 |
|---------|---------|
| 用户要求跳过某方法 | 允许跳过，但标注"⚠️ 跳过[方法名]可能导致[风险]，建议在PRD中标注待确认" |
| 用户要求增加某方法 | 允许增加，检查该方法的前置依赖是否满足，不满足则提示 |
| 用户要求替换某方法 | 允许替换，检查替代方法是否能达到同等产出 |
| 多场景叠加方法冲突 | 按 D4>D3>D2>D1 优先级取高复杂度维度的方法 |
