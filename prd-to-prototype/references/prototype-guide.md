# HTML 高保真可交互原型生成指南

本文件为「需求PRD到产品原型」Skill 的原型生成规范。模块三生成原型时读取本文件。

---

## 一、技术规范

- **单HTML文件**：所有CSS/JS内联，浏览器双击即可运行
- **外部依赖**：**禁止使用外部CDN**（内网/离线环境会样式崩溃）；所有CSS/JS必须内联；图标用emoji或内联SVG
- **命名**：`{项目名}-原型-{日期}.html`
- **位置**：工作区根目录
- **浏览器兼容**：Chrome/Edge/Safari/Firefox 现代浏览器，双击打开无JS报错
- **XSS防护**：所有用户输入内容（项目名、功能名、页面名、交互文案、模拟数据等）写入HTML前须做HTML实体转义（`<`→`&lt;` `>`→`&gt;` `&`→`&amp;` `"`→`&quot;` `'`→`&#x27;`），防止注入恶意脚本
- **交付前校验**：生成后检查HTML无 `http://` 或 `https://` 外部引用（CDN检测），确保纯内联

## 二、保真度分级策略

### 2.1 两级保真度定义

原型支持**演示级高保真**和**评审级中保真**两级保真度，在 PRD 确认关卡时由用户选择：

| 维度 | 演示级高保真 | 评审级中保真 |
|------|-------------|-------------|
| **定位** | 客户宣讲、投资人演示、对外汇报 | 内部评审、工程交接、快速验证 |
| **视觉精度** | 接近真实产品：真实配色、图标、间距、阴影、圆角 | 信息架构为主：基础配色、占位图标、标准间距 |
| **组件完整度** | 全组件库（含轮播/步进器/搜索/筛选/骨架屏等高级组件） | 基础组件库（导航/按钮/表单/卡片/弹窗/标签） |
| **多状态展示** | 每个核心页面展示5种状态（默认/加载/空/错误/成功） | 核心页面展示默认状态，关键页可加空状态 |
| **交互完整度** | 页面跳转+表单提交+状态切换+弹窗+筛选+搜索+滑动等全交互 | 页面跳转+表单提交+弹窗+Tab切换等基础交互 |
| **模拟数据** | 真实感数据（"招牌牛肉面 ¥28"），≥10条列表数据 | 基础数据（"商品A/商品B"），3-5条列表数据 |
| **走查脚本** | ✅ 必须附走查脚本（步骤序号/页面/操作/预期效果） | 可选附走查脚本 |
| **PRD对齐校验** | ✅ 必须执行并输出校验报告 | ✅ 必须执行并输出校验报告 |
| **动画过渡** | 页面切换/弹窗/加载有过渡动画 | 无动画或最小动画 |
| **PC端支持** | ✅ 支持PC画布（1440px）+ PC组件布局 | 支持PC画布，基础布局 |

### 2.2 保真度选择时机

在**模块二→模块三确认关卡**时（PRD确认通过后），向用户提供保真度选择：

```
PRD已确认 ✅

接下来生成产品原型，请选择保真度级别：

A) 演示级高保真
   适用：客户宣讲、投资人演示、对外汇报
   特点：视觉精致、全状态展示、附走查脚本、生成耗时较长

B) 评审级中保真
   适用：内部评审、工程交接、快速验证
   特点：信息架构为主、核心状态、生成较快

C) 不确定，帮我推荐
   我会根据你的PRD复杂度和使用场景推荐

请选择（A/B/C）：
```

### 2.3 验证目的维度（方法选择引擎集成）

保真度选择升级为"保真度 + 验证目的"双维度匹配。保真度由用户选择（演示级/评审级），验证目的由场景画像推荐：

| 验证目的 | 推荐保真度 | 对应方法 | 适用场景 | 触发条件 |
|---------|-----------|---------|---------|---------|
| 验证**信息结构** | 低保真线框图(M35) | 灰盒子+占位文字 | 需求早期，结构未定 | D5=高不确定性 |
| 验证**视觉感受** | 中保真→高保真(M36→M37) | 色彩/图标/真实文案 | 客户演示、视觉评审 | 默认 |
| 验证**操作流程** | 可交互原型(M38) | 页面跳转/状态切换/微交互 | 操作流程验证、可用性测试 | D4=复杂流程 |
| 验证**多端一致性** | 响应式设计(M48) | 断点+栅格+组件适配 | 多端产品 | D6=多端 |

**原型前置方法根据场景选择**：

| 场景特征 | 原型前置方法 | 说明 |
|---------|------------|------|
| D4=复杂流程 | 用户流程图(M39) + 信息架构图(M40) | 先定路径再画页面 |
| D6=多端 | 设计系统(M41) + 组件库(M42) + 响应式(M48) | 先建规范再出页面 |
| D5=高不确定性 | 低保真(M35) → 可用性测试(M44) → 迭代 | 先低保真快速验证再迭代 |
| D6=单端·简单 | 直接高保真(M37) → 走查(M43+M47) | 跳过低保真，直接出高保真 |

**走查方法固定+可选**：

| 走查方法 | 是否固定 | 说明 |
|---------|---------|------|
| 原型走查清单(M47) | ✅ 固定 | 所有原型交付前必做 |
| 尼尔森十大原则(M43) | ✅ 固定 | 所有高保真原型交付前必做 |
| 可用性测试(M44) | ⬜ 可选 | D5=高不确定性时推荐 |
| A/B测试(M45) | ❌ 不适用 | 上线后方法，原型阶段用可用性测试替代 |

> 各方法详细指引见 `method-toolkit.md` 的 M35-M49 段落，按场景诊断推荐的方法编号按需读取。

### 2.4 推荐逻辑（用户选C时）

## 四、视觉设计规范（浅色背景·简约清爽科技风）

> **全局强制风格**：所有 HTML 原型统一采用浅色背景+简约清爽科技风。不论用户是否指定，默认执行。

### 4.1 设计哲学

- **简约**：留白充足，信息密度适中，视觉层次靠间距和字重而非颜色堆砌
- **清爽**：浅色底+深色字，高对比度阅读体验，拒绝深色底白字
- **科技感**：克制的蓝色主调+微妙的阴影分层+细腻的过渡动画，传达专业可靠

### 4.2 设计令牌系统（所有原型必须遵循）

```css
:root {
  /* ===== 背景色层级 ===== */
  --bg-page: #F8FAFC;        /* 页面底色（最浅） */
  --bg-section: #F1F5F9;    /* 区块底色 */
  --bg-card: #FFFFFF;       /* 卡片底色（纯白） */
  --bg-hover: #F0F7FF;       /* 悬停底色（微蓝） */

  /* ===== 文字色层级 ===== */
  --text-primary: #1A1A1A;   /* 主标题/正文主色 */
  --text-secondary: #555555; /* 次要文字 */
  --text-tertiary: #8A8A8A;  /* 辅助/提示文字 */
  --text-on-primary: #FFFFFF;/* 主色背景上的文字 */

  /* ===== 品牌主色（科技蓝系） ===== */
  --color-primary: #2563EB;      /* 主色蓝 */
  --color-primary-hover: #1D4ED8;/* 悬停深蓝 */
  --color-primary-light: #EFF6FF;/* 浅蓝底 */
  --color-accent: #0891B2;       /* 辅助青 */
  --color-success: #059669;      /* 成功绿 */
  --color-warning: #F59E0B;      /* 警示橙 */
  --color-danger: #EF4444;       /* 危险红 */

  /* ===== 阴影层级（科技风关键：微妙而有层次） ===== */
  --shadow-xs: 0 1px 2px rgba(15, 23, 42, 0.04);
  --shadow-sm: 0 2px 4px rgba(15, 23, 42, 0.05), 0 1px 2px rgba(15, 23, 42, 0.03);
  --shadow-md: 0 4px 12px rgba(15, 23, 42, 0.06), 0 1px 3px rgba(15, 23, 42, 0.04);
  --shadow-lg: 0 12px 24px rgba(15, 23, 42, 0.08), 0 4px 8px rgba(15, 23, 42, 0.04);

  /* ===== 圆角 ===== */
  --radius-sm: 6px;
  --radius: 10px;
  --radius-lg: 14px;

  /* ===== 间距（8px倍数体系） ===== */
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-6: 24px;
  --space-8: 32px;

  /* ===== 过渡（统一缓动曲线） ===== */

  /* ===== 字体 ===== */
  --font-family: -apple-system, "Microsoft YaHei", "PingFang SC", "Segoe UI", sans-serif;
  --font-mono: "JetBrains Mono", "Consolas", monospace;
}
```

### 4.3 风格执行规则

| 规则 | 要求 | 禁止 |
|------|------|------|
| **背景** | 页面 `--bg-page`，卡片 `--bg-card` 纯白 | 深色底（#1E293B等）作为主背景 |
| **侧边栏** | 浅色底 `#FFFFFF` + 右边框 + 微阴影 | 深色侧边栏 |
| **文字** | 深色文字在浅色背景上 | 浅色文字在浅色背景上（低对比度） |
| **主色** | 科技蓝 `#2563EB` 为主，青 `#0891B2` 为辅 | 多种饱和色混用 |
| **阴影** | 三级阴影分层（xs/sm/md/lg），hover 上浮 | 单层重阴影 / 无阴影 |
| **圆角** | 卡片 `--radius`（10px），按钮 `--radius-sm`（6px） | 直角 / 过大圆角（>20px） |
| **过渡** | 统一 `--transition` 缓动曲线 | 无过渡 / 过快（<0.1s）/ 过慢（>0.5s） |
| **间距** | 8px 倍数体系，留白充足 | 随意间距（3px/7px/13px等） |
| **emoji** | 功能性使用，每个有明确语义 | 装饰性堆砌 |

### 4.4 组件视觉标准

| 组件 | 默认态 | 悬停态 | 激活态 |
|------|--------|--------|--------|
| **卡片** | `--bg-card` + `--shadow-sm` + `--radius` | `--shadow-md` + `translateY(-2px)` | — |
| **主按钮** | `--color-primary` 底 + 白字 + `--shadow-sm` | `--color-primary-hover` + `--shadow-md` + `translateY(-1px)` | `scale(0.97)` |
| **次按钮** | `--bg-card` + `--color-primary` 字 + 边框 | `--color-primary-light` 底 | `scale(0.97)` |
| **导航项** | `--text-secondary` 字 | `--bg-hover` 底 + `--text-primary` 字 | `--color-primary-light` 底 + `--color-primary` 字 + 左边框 |
| **输入框** | 白底 + `--shadow-xs` + `--radius-sm` | focus: `--color-primary` 边框 + 蓝色光晕 | — |
| **标签/徽标** | 浅色底 + 深色字（如浅蓝底+蓝字） | — | — |

### 4.5 移动端 vs PC端差异

| 维度 | 移动端（375px） | PC端（1440px） |
|------|----------------|----------------|
| 画布 | `--bg-page` 底色 | `--bg-page` 底色 |
| 卡片间距 | 12px | 24px |
| 卡片内边距 | 12-16px | 20-24px |
| 阴影 | `--shadow-sm` 为主 | `--shadow-sm`/`--shadow-md` 混用 |
| 字号 | 正文14px / 标题17px | 正文14px / 标题18px |
| 圆角 | `--radius`（10px） | `--radius`（10px）统一 |

### 4.6 禁止项清单（交付前自检）

- [ ] 无深色底白字（侧边栏/导航/头部均浅色）
- [ ] 无外部CDN引用（纯内联）
- [ ] 无低对比度文字（浅色底上浅色字）
- [ ] 无无阴影的悬浮卡片
- [ ] 无随意间距（全部8px倍数）
- [ ] 无直角元素（全部有圆角）
- [ ] 无无过渡的交互（hover/active有动画）
- [ ] 主色为蓝青绿系，非其他色系

## 六、多状态展示规范

### 6.1 五种必须状态

| 状态 | 说明 | 实现方式 | 演示级 | 评审级 |
|------|------|---------|--------|--------|
| **默认态** | 有数据的正常展示 | 标准组件+模拟数据 | ✅ | ✅ |
| **加载态** | 数据加载中 | 骨架屏（演示级）或spinner（评审级） | ✅ 骨架屏 | ✅ spinner |
| **空状态** | 无数据（新用户/无搜索结果） | 空状态组件（图标+文案+引导按钮） | ✅ | ✅ 核心页 |
| **错误态** | 网络异常/加载失败 | 错误提示+重试按钮 | ✅ | ❌ |
| **成功态** | 操作完成（提交成功/兑换成功） | 成功页或成功Toast+结果展示 | ✅ | ✅ |

### 6.2 状态展示规则

| 规则 | 说明 |
|------|------|
| 核心列表页必须有空状态 | 商品列表、订单列表、搜索结果等列表页须展示空状态 |
| 核心列表页必须有加载态 | 演示级用骨架屏，评审级用spinner |
| 表单提交必须有成功态 | 提交后展示成功反馈（成功页或Toast） |
| 演示级附加错误态 | 关键操作（兑换/支付/提交）须展示失败错误态+重试 |
| 状态可切换 | 原型中提供状态切换入口（仅演示用） |

### 6.3 状态切换器实现方案

在原型HTML中，每个核心页面顶部加一个**状态切换器**（仅演示用，实际产品中不存在）：

```html
<!-- 状态切换器（仅原型演示用） -->
<div class="state-switcher">
  <span class="state-switcher-label">🎭 状态预览：</span>
  <button class="state-btn active" onclick="switchState('default')">默认</button>
  <button class="state-btn" onclick="switchState('loading')">加载中</button>
  <button class="state-btn" onclick="switchState('empty')">空数据</button>
  <button class="state-btn" onclick="switchState('error')">错误</button>
</div>
```

```javascript
// 状态切换函数
function switchState(state) {
  // 隐藏当前页面所有状态容器
  var activePage = document.querySelector('.page.active');
  activePage.querySelectorAll('.state-container').forEach(function(c) {
    c.style.display = 'none';
  });
  // 显示选中状态
  var target = activePage.querySelector('.state-container[data-state="' + state + '"]');
  if (target) target.style.display = 'block';
  // 更新按钮高亮
  activePage.querySelectorAll('.state-btn').forEach(function(b) {
    b.classList.remove('active');
  });
  event.target.classList.add('active');
}
```

每个核心页面的内容区用 `.state-container[data-state="xxx"]` 包裹不同状态的内容：

```html
<!-- 默认状态 -->
<div class="state-container" data-state="default" style="display:block;">
  <!-- 正常列表内容 -->
</div>
<!-- 加载状态 -->
<div class="state-container" data-state="loading" style="display:none;">
  <div class="skeleton">...</div>
</div>
<!-- 空状态 -->
<div class="state-container" data-state="empty" style="display:none;">
  <div class="state-empty">...</div>
</div>
<!-- 错误状态 -->
<div class="state-container" data-state="error" style="display:none;">
  <div class="state-error">...</div>
</div>
```

## 七、PRD对齐校验机制

### 7.1 标注规范（支撑校验）

```html

<!-- F06: 积分兑换 -->

```

### 7.2 校验一：Page Map → 原型页面覆盖度

## 十、生成流程（9步）

1. **读取PRD**：提取目标端、Page Map（页面清单）、功能清单（含依赖+归属页面）、用户流程（Mermaid）、交互说明、验收标准、非目标
2. **确定保真度**：根据用户在确认关卡选择的保真度级别（演示级/评审级）决定组件范围、状态数量、数据精度
3. **按需读取HTML模板CSS/JS分组**：
   - 始终读取 G1-基础组件 CSS + HTML骨架结构 + JS基础函数
   - 演示级高保真 → 追加读取 G2-演示级组件 CSS/JS
   - 目标端含PC → 追加读取 G3-PC端组件 CSS
   - 模板文件中用 `<!-- CSS-GROUP: basic/demo/pc -->` 注释标注各组边界，读取时定位标注截取即可
4. **按Page Map生成页面**：每个P0页面 → 生成一个 `.page` div，加 `<!-- Page: P0X 页面名 -->` 标注
5. **按功能清单实现交互**：每个P0功能 → 该页面至少一个可操作元素，加 `<!-- F0X: 功能名 -->` 标注
6. **按Mermaid流程实现跳转**：流程图中的动作节点 → 页面跳转逻辑，判断节点 → 条件分支交互
7. **多状态展示**：核心页面用 `state-container` 包裹默认/加载/空/错误状态，加状态切换器
8. **PRD对齐校验**：执行Page Map覆盖度+功能点覆盖度校验，输出校验报告
9. **生成走查脚本**：基于Mermaid流程生成步骤表格，嵌入原型HTML顶部折叠面板；浏览器实测：页面可切换、交互可响应、控制台无JS报错、PC端不溢出
