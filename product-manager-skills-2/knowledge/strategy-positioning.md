# 策略与定位

涵盖公司/市场研究、定位、产品策略、优先级和路线图规划的压缩知识模块。

## 公司与市场研究

### 公司研究框架

从7个维度研究：公司概述、高管引语、产品洞察、转型策略、组织影响、未来路线图、产品主导增长。

**研究步骤：**
1. 定义范围：公司名称、研究目的、3个关键问题
2. 收集概述：总部、行业、创立、规模、关键里程碑
3. 提取高管引语：CEO（愿景）、COO（运营）、VP产品（策略）、集团PM（计划）。引用来源+日期。优先最近12-24个月。
4. 记录产品洞察：策略概述、最近发布及市场影响、产品理念/原则
5. 识别转型策略：数字化（架构转变）、AI（产品中的ML）、敏捷（方法论采用）
6. 映射组织PM影响：PM在战略决策中的作用、跨职能协作模式、职业道路
7. 分析未来路线图：计划举措、预期挑战、竞争威胁
8. 记录PLG洞察：自助入职、数据驱动决策、激活/留存/扩展模式
9. 综合：3个战略原则、3个PM教训、未回答的问题

**来源优先级：** 财报电话会议 > 播客访谈 > 会议演讲 > 高管博客 > LinkedIn > 公司网站。比"关于我们"页面更深入。

### PESTEL分析

六个宏观环境因素。首先定义范围：产品名称、分析目的、地理范围、时间跨度。

| 因素 | 关键问题 | 示例来源 |
|------|----------|----------|
| **政治** | 政府政策、稳定、贸易法规、税收 | 立法数据库、贸易报告 |
| **经济** | GDP增长、通胀、汇率、消费支出 | 人口普查局、劳工统计局、世界银行 |
| **社会** | 人口统计、文化趋势、生活方式转变、态度 | 皮尤研究、人口研究 |
| **技术** | 进步、研发活动、自动化、数字采用 | Gartner、行业报告 |
| **环境** | 气候影响、可持续性、资源稀缺、绿色法规 | 如果影响很小，诚实说明 |
| **法律** | 合规（GDPR、AI法案）、知识产权、雇佣法、安全法规 | 法律数据库、监管文件 |

**对于每个因素：** 陈述对你的产品的具体影响及战略行动含义。通用陈述（"法规存在"）是无用的。

**综合输出：** 前3个机会（带行动）、前3个威胁（带缓解）、3个战略建议。每年或重大外部事件时重新评估。

### TAM/SAM/SOM计算

三层市场估算与引用支持的数据。

**TAM** = 100%捕获时的总市场需求。最广泛。
**SAM** = 按地理、公司特征、产品约束缩小的TAM。"我们实际能触达谁？"
**SOM** = 按竞争、GTM能力缩小的SAM。"我们在1-3年内能捕获什么？"通常第1-3年为SAM的1-20%。

**计算过程：**
1. 定义问题空间（B2B SaaS、消费者金融科技、医疗等）
2. 选择地理区域（美国 = 人口普查/劳工统计局数据；欧盟 = 欧盟统计局；全球 = 世界银行/IMF）
3. 识别有人口和收入数据的行业细分
4. 缩小到目标客户细分与公司特征/人口统计

**输出格式：** 每层显示人口估算、市场规模（美元）、计算数学、来源引用（带URL）和关键假设。

**SOM第1-3年预测：** 包括客户数量和收入。以GTM约束为基础（销售能力、转化率、营销预算）。

**数据来源：** 美国人口普查局、劳工统计局、IBISWorld、Statista、Gartner、Forrester、世界银行、欧盟统计局。

## 产品定位

### Geoffrey Moore定位陈述

来自《跨越鸿沟》的两部分结构：

**价值主张：**
- **针对** [特定目标客户/人物角色]
- **谁需要** [未被满足的需求——痛点、收益、JTBD]
- [产品名称]
- **是一种** [产品类别]
- **能够** [收益陈述——成果，不是功能]

**差异化陈述：**
- **不同于** [主要竞争对手或实际替代行为]
- [产品名称]
- **提供** [独特差异化——成果，不是功能]

### 压力测试（应用于每个草稿）

1. 目标客户能在"针对"陈述中认出自己吗？
2. 你能指出验证需求的研究吗？
3. 类别是否将你锚定在正确的竞争对手（或限制你）？
4. 差异化是否可以用演示、案例研究或数据证明？
5. 这个定位有助于回答"我们应该构建功能X吗？"

### 定位工作坊流程（交互式）

5个问题的发现序列：
1. **目标客户细分** -- B2B SMB / B2B企业 / B2C大众 / B2C细分（或自定义）
2. **未被满足的需求** -- 从Q1适应到细分（时间浪费、缺乏可见性、合规负担、昂贵低效）
3. **产品类别** -- 锚定买家评估。除非有强烈理由创建类别，否则选择现有类别。
4. **关键收益** -- 成果，不是功能。必须可衡量（节省的时间、减少的错误、削减的成本）。
5. **竞争差异化** -- 命名实际竞争对手或替代行为。在成果上差异化。

输出：完整定位陈述 + 一句话总结 + 压力测试检查清单 + 下一步（用5个客户测试、与利益相关者分享、应用到制品）。

### 定位质量标准

- 目标具体性：可向招聘者描述
- 需求清晰度：情感共鸣，不是通用
- 类别契合度：帮助买家评估，不是"下一代平台"
- 成果焦点：用户获得什么，不是产品有什么
- 竞争对手诚实：买家考虑的真实替代品
- 差异化持久性：6个月内不可复制

## 产品策略

### 策略会议阶段（2-4周过程）

**阶段1：定位与市场上下文（第1-2天）**
- 运行定位工作坊。定义原型人物。映射JTBD。
- 决策门槛：有足够的客户上下文吗？如果否，运行5-10次发现访谈（+1周）。

**阶段2：问题框架与验证（第3-5天）**
- 运行问题框架画布。创建正式问题陈述。可选：客户旅程图。
- 决策门槛：问题验证了？如果否，运行发现访谈（+1周）。

**阶段3：解决方案探索（第2周，第1-3天）**
- 生成机会解决方案树（3个机会，每个3个解决方案，POC建议）。定义史诗假设。
- 决策门槛：需要测试解决方案？如果是（高度不确定性），运行实验（+1-2周）。

**阶段4：优先级与路线图（第2周，第4-5天）**
- 选择优先级框架。为史诗评分和排名。按发布顺序安排路线图。可选：用于高管演示的TAM/SAM/SOM。

**阶段5：利益相关者对齐（第3周）**
- 展示策略：定位 + 问题 + 解决方案 + 优先级 + 路线图。
- 包括"路线图上没有什么及原因"。根据反馈完善。

**阶段6：执行规划（第4周）**
- 使用拆分模式拆分最高史诗（工作流、CRUD、业务规则）。编写带有验收标准的用户故事。规划第一个冲刺。

**决策门槛是强制性的。** 跳过它们会导致为未验证问题构建解决方案或在低不确定性活动上浪费时间的后果。

## 优先级

### 框架选择矩阵

| 上下文 | 推荐框架 | 为什么 |
|--------|----------|--------|
| Pre-PMF，数据最少，小团队 | **ICE** 或 **价值/努力矩阵** | 轻量级、直觉检验、快速评分 |
| 早期PMF，一些数据，对齐团队 | **RICE** | 结构化但不压倒性；平衡数据+速度 |
| 成熟产品，丰富数据 | **机会评分** 或 **Kano** | 利用分析、客户调查 |
| 多个利益相关者，未对齐 | **加权评分** 或 **买功能** | 透明、共识建设 |
| 大组织，跨团队依赖 | **延迟成本** 或 **影响映射** | 处理协调复杂性 |
| 战略赌注vs.快速胜利 | **价值/努力矩阵** | 视觉化、直觉权衡对话 |

### RICE评分

公式：`(触达 x 影响 x 信心) / 努力`
- **触达：** 每月/每季度受影响的用户
- **影响：** 1（最小）、2（高）、3（巨大）
- **信心：** 50%（低数据）、80%（良好数据）、100%（确定）
- **努力：** 人月（包括设计、工程、QA）

使用RICE作为输入，不是自动化。当战略上下文需要时，PM判断覆盖分数。原始评分后始终调整战略契合度。

### 优先级决策逻辑

4个问题评估以选择框架：
1. 产品阶段（pre-PMF / 早期PMF / 成熟 / 多产品）
2. 团队上下文（小+专注 / 跨职能对齐 / 利益相关者未对齐 / 大组织）
3. 主要挑战（想法太多 / 利益相关者分歧 / 没有数据驱动流程 / 战略vs.战术权衡）
4. 数据可用性（最少 / 一些 / 丰富）

坚持一个框架6-12个月。只有阶段或上下文改变时才重新评估。

## 路线图规划

### 路线图类型

| 类型 | 结构 | 适用于 |
|------|------|--------|
| **现在/下一步/以后** | 承诺/高信心/探索 | 敏捷团队、不确定性、持续发现 |
| **主题驱动** | 战略主题（留存、企业、移动） | 高管沟通、战略意图 |
| **时间线（季度）** | Q1: A, B; Q2: C, D; Q3: E, F | 资源规划、利益相关者沟通 |
| **功能驱动** | 列出功能没有上下文 | 反模式。没有战略叙事。 |

### 路线图规划过程（5阶段，1-2周）

**阶段1：收集输入（第1-2天）**
- 业务目标：前3个公司优先事项、关键指标、战略赌注
- 客户问题：前3-5个验证的痛点（来自发现）
- 技术约束：阻碍、赋能投资、迁移
- 利益相关者请求：销售、营销、CS输入（尚未承诺）

**阶段2：定义举措（第3-4天）**
- 写史诗假设："我们相信[构建X]用于[人物角色]将实现[成果]因为[假设]。"
- T恤尺寸努力：S（1-2周）、M（3-4周）、L（2-3月）、XL（3+月）
- 将每个史诗映射到主要业务成果

**阶段3：优先级（第5天）**
- 使用优先级顾问选择框架
- 协作评分所有史诗（PM + 工程 + 产品领导）
- 调整分数的战略契合度（战略覆盖是合法的）

**阶段4：排序（第6-7天）**
- 映射依赖（技术和逻辑）
- 分配到现在（承诺）、下一步（高信心）、以后（探索）
- 与工程验证可行性

**阶段5：沟通（第2周）**
- 演示结构：战略上下文、路线图概述、每季度深入、路线图上没有什么（及原因）、依赖和风险
- 专注于战略叙事："为什么X优先于Y"
- 框架为计划，不是承诺："根据学习可能变更"
- 收集反馈、完善、发布内部（及可选外部格式：现在/下一步/以后）

## 质量门

### 定位反模式
- **"针对所有人"** -- 没有人觉得是针对他们的。选择第一个细分；以后扩展。
- **收益中的功能蔓延** -- "AI、自动化、分析"是功能列表。以成果为首。
- **虚构竞争对手** -- "不同于过时的遗留系统"是稻草人。命名实际替代品。
- **类别混淆** -- "数字化转型的下一代平台"没有心智货架。选择已知类别或承诺创建类别。
- **无证据的差异化** -- 没有证据的"革命性AI"是噪音。使其可证伪。

### 研究反模式
- **表面研究** -- 找高管访谈和产品博客，不只是"关于我们"页面。
- **无引用** -- 始终引用来源+日期。无法验证 = 低可信度。
- **无行动的分析** -- PESTEL和公司研究必须以战略建议结束，不只是列表。
- **过时信息** -- 优先最近12-24个月来源。

### 市场估算反模式
- **无引用的TAM** -- 引用行业报告（Gartner、IBISWorld、Statista）带URL。
- **SOM = SAM** -- 没有市场竞争为零的市场。SOM = 第1-3年SAM的1-20%。
- **无人口估算** -- 始终包括客户数量以及美元金额。
- **忽视GTM约束** -- SOM基于销售能力、转化率、营销预算。

### 优先级反模式
- **阶段错误的框架** -- Pre-PMF创业公司使用10个标准的加权评分会扼杀速度。
- **框架震荡** -- 每季度切换框架导致混乱。坚持6-12个月。
- **分数作为教条** -- 分数是输入，不是自动化。战略上下文覆盖。
- **PM独自评分** -- 协作评分（PM + 设计 + 工程）建立认同。
- **HiPPO优先级** -- 任何框架都比"谁声音最大"好。

### 路线图反模式
- **功能驱动路线图** -- 将史诗框架为带有成功指标 hypotheses，不是功能名称。
- **路线图作为承诺** -- 作为战略计划沟通，根据学习可能变更。
- **无依赖映射** -- 与工程验证序列。未映射依赖 = 季度阻塞。
- **PM独自路线图** -- 从所有利益相关者收集输入（第1阶段），展示草稿获取反馈（第5阶段）。
- **无高管赞助的策略** -- 预先获得高管承诺。在开始前安排对齐演示。
