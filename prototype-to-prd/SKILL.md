# 门户端 HTML 原型 → PRD 生成

## 触发场景

用户在完成门户端 HTML 原型设计后，调用本技能将原型转化为需求说明文档（PRD）。触发条件：

- 用户提供 HTML 原型文件路径并要求"输出 PRD" / "生成需求说明" / "转需求文档"
- 用户要求"基于原型输出前台页面需求文档"
- 用户说"像我之前那样把原型输出成带交互和数据来源的文档"

## 核心原则

**前台门户需求只描述三件事，不描述视觉细节：**
1. **要素** — 页面有什么（区块、字段、按钮、卡片）
2. **交互** — 点击哪里跳转到什么页面 / 触发什么行为
3. **数据来源** — 数据从哪个接口/模块获取、取数条件是什么

**不描述的内容：** 颜色、间距、圆角、字号、阴影等视觉样式。顶部导航与底部为标准框架内容，不出现在文档中。

## 工作流程

### 第一步：判断需求类型

与用户确认输出范围：
- **单页面** → 输出单页面需求说明（一篇文档，含一个页面）
- **多页面** → 逐页输出需求说明 + 最终汇总为一份完整 PRD
- **仅汇总** → 已有各页面需求说明，直接汇总为完整 PRD

若用户未明确，默认按"多页面完整 PRD"模式执行。

### 第二步：读取原型文件

逐页面读取 HTML 原型文件，梳理页面要素：

**要素提取要点：**
- 每个 `<section>` 或 `<div>` 带有 `id` 属性的，视为独立区块（原型ID取自 `id` 属性值）
- 区块内的标题、输入框、按钮、链接、卡片网格、Tab 切换标签、分页组件等，逐一识别
- 卡片类组件提取卡片内的所有字段（名称、标签、价格、按钮等）
- 枚举类元素（分类Tab、筛选芯片）记录完整枚举值或注明"取自XX数据源"

**示例要素结构：**
```
区块1：搜索区（id: sec-hero）
  - 标题、副标题
  - 搜索维度Tab：按服务事项 / 按服务机构
  - 搜索输入框 + 搜索按钮

区块2：筛选栏（id: sec-filter）
  - 分类芯片：全部、财税服务、知识产权...（取自【商品小类】）
  - 标签芯片：全部、优质服务产品
  ...
```

### 第三步：编写交互说明

为每个可交互元素编写交互行为表格：

```
| 元素 | 交互 |
|:---|:---|
| 维度切换Tab | 默认选中"按服务事项"，点击切换 |
| 搜索按钮 | 按当前维度+关键词执行搜索并跳转结果页 |
| 卡片"查看详情" | 跳转**服务详情页** |
| "查看更多" | 跳转**服务列表页**（携带当前选中分类参数） |
```

**跳转格式规则：**
- 跳转目标用 `**加粗**`：跳转**服务详情页**
- 携带参数用 `（携带XX参数）` 后缀
- 纯展示标注：纯展示，无点击跳转
- 弹框/表单标注：弹出**入驻申请表单**

**跳转关系梳理：**
- 首页 → 各列表页（"查看更多"）/ 各详情页（卡片）
- 列表页 → 详情页（"查看详情"）
- 详情页之间：服务详情"服务商" → 机构详情；机构详情"服务产品" → 服务详情；机构详情"查看全部" → 服务列表

### 第四步：编写数据来源

为每个数据区块编写数据来源说明：

```
**数据来源**：服务商品列表接口，条件：
- 上架状态=已上架
- 按推荐排序取前6条
- 带"优质服务产品"标签的数据，打上对应角标
```

**数据来源规则：**
- 枚举来源标注：取自【商品小类】、取自机构标签体系
- 计数类标注统计口径：审核通过的总数、已上架商品数统计
- 跨模块标注：专家列表接口（专家管理独立模块）
- 排序规则标注：按推荐排序 / 按排序值降序 / 按创建时间降序
- 数量限制标注：取前N条 / 分页默认9条/页

### 第五步：要素核对

逐区块核对原型要素，确保文档无遗漏：

**核对清单格式：**
```
| 区块 | 原型要素 | 文档是否覆盖 |
|:---|:---|:---:|
| 搜索区 | 标题/维度Tab/输入框/搜索按钮 | ✅ |
| 筛选 | 分类(10项)/标签(3项)/价格 | ✅ |
```

**核对规则：**
- 每个区块的每个可见元素必须出现在核对清单中
- 如有遗漏，补充后重新核对
- 核对通过后展示结果

### 第��步：输出文档

**单页面模式：** 输出一份需求说明 `.md` 文件，命名：`需求说明-[页面名称].md`

**多页面模式：**
1. 逐页输出需求说明 `.md` 文件
2. 最后汇总为完整 PRD，命名：`PRD_服务商城PC端_[日期].md`

**完整 PRD 汇总要求：**
- 需求概述（背景 + 功能清单表 + 页面导航关系 Mermaid 图）
- 公共规则章节（标签体系、数据源、排序规则、脱敏规则等）
- 各页面章节（合并所有单页面的需求说明内容）
- 全局待确认事项
- 评审记录占位

### 第七步：按用户反馈修正

输出文档后，根据用户反馈更新内容：
- 原型调整 → 重新读取原型 → 更新文档
- 逻辑修正 → 直接更新文档对应章节
- 增删字段/筛选项 → 同���更新要素描述 + 交互表 + 数据来源 + 核对清单

## 输出规范

- 所有输出以简体中文为主
- 表格使用标准 Markdown 格式（`:---` 左对齐、`:---:` 居中）
- 交互描述使用 `→` 表示跳转
- 页面名称统一用**加粗**标注跳转目标
- 文件写入当前工作空间目录
