# 集成边界参考

## 工程定位
- 先确认目标项目、子模块、页面目录、相似页面和代码风格。
- HZERO 项目先确认路由、菜单权限、页面容器和 i18n，再实现页面内容。
- Choerodon 页面先确认 DataSet 边界、字段、查询/提交协议和组件绑定。

## 路由和权限
- 不根据 Figma 页面标题编造 route path、菜单编码或权限码。
- 行操作、工具栏按钮和页面入口都需要确认权限来源。
- 若权限未确认，只输出权限待确认项和组件映射建议；不得生成无权限绑定的页面骨架。

## i18n
- Figma 文案可以作为默认中文文案来源。
- i18n key 命名必须遵循项目现有模式；未确认时不要批量生成看似真实的 key。
- 交付时列出新增文案清单，方便后续接入国际化资源。

## 数据层
- Figma 不提供接口契约；DataSet `transport`、service URL、HTTP method、参数和响应结构必须另行确认。
- 有相似页面时，只复用不违反当前标准的请求封装和目录模式；DataSet 请求仍应写在 `transport` 中并返回 request config，不复用 DataSet import/call 业务 service 的旧写法。
- 无接口契约时，只生成字段结构和方法占位说明，不生成 runnable-looking 请求。

## 样式和响应式
- 先复用项目布局、主题变量、spacing token 和组件样式。
- 避免绝对定位复刻设计稿；使用栅格、Flex、Grid 或组件库布局能力。
- 桌面和移动端都要定义最低可接受行为：折行、滚动、列隐藏或抽屉宽度。

## 资源和图标
- Figma 图片、SVG、icon 可下载为项目资源，但必须确认资源目录和命名规范。
- 装饰性图标优先映射到项目图标库；只有无法映射时才下载静态资源。
- 不把包含业务数据的截图作为页面内容。

## 验证
- 先发现项目 scripts 和技术栈，再决定 lint、typecheck/tsc、test、build。
- 设计转代码至少验证：编译通过、页面可打开、主要交互无控制台错误、响应式基础可用。
- 未能验证 Figma 视觉一致性时，说明仅完成结构/代码验证。
