## 二、关键章节规范

### 1. 待确认项（阻塞编码项）

方案阶段显式登记悬而未决的问题，**每条必须给默认实现**，供 L2 强制确认清单（v2.3 §4）消费：

`| 序号 | 问题描述 | 所属 TECH | 未确认时编码阶段的默认实现 |`

- 涉及库表结构、接口契约、技术选型的待确认项，主理人必须转 L2 强制确认清单，等用户答复后回填本文档
- 未回填的待确认项不得进入工序 2.3 开发计划拆分

### 2. 技术点（TECH）清单与形态分类

每个技术设计单元一行，形态决定必填工件（见 §4），**禁止机械复制全部子节、禁止为凑节号保留空节**：

`| TECH 编码 | 名称 | 描述 | 形态 | 优先级(P0-P3) | 依赖 TECH | 覆盖需求项 | 涉及文件 | 验收方式 |`

**形态编码与必填工件**（组合形态取并集）：

| 形态 | 适用场景 | 必填工件（缺一视为未闭合） |
|---|---|---|
| **A-QUERY** | 列表/详情/只读查询 | 入口(API) + 逐字段请求/响应契约 + 复杂查询完整SQL（简单读写在持久层矩阵写 Repository 契约）+ DTO/Entity 决策 + 错误矩阵(如有) |
| **A-COMMAND** | 创建/更新/删除/提交类写操作 | 入口(API) + 逐字段契约 + 关键方法(事务/步骤/异常) + 数据落点 + 错误矩阵 |
| **A-SYNC** | 同步/集成/Job/外部拉取 | 入口(Job/REST) + 主表+逐子表字段级映射（每子表独立小节）+ 关键方法 + 事务/锁/失败策略 + 持久化落点 |
| **A-CROSS** | 权限/边界/横切约束 | permission 清单 + 附着接口/Job 列表 + 租户/只读边界（可无独立 SQL） |
| **A-INFRA** | 公共骨架/常量/工具 | 实现文件清单中的类职责（不强制独立 API） |

### 3. 需求覆盖清单【强制，100% 覆盖】

PRD（13 要素版）每个功能需求的逻辑点/验收点必须映射到 TECH 落点：

`| FDS/PRD 来源章节 | 业务逻辑点/验收标准/字段 | TECH 编码 | 技术设计落点/证据 |`

**硬规则：本清单完成前，不得开始详细设计（§3）。** 该清单同时是工序 3.4 业务验收走查（三对齐）与追溯矩阵（v2.3 §8）的直接上游。

### 4. 详细设计 TECH 章节写作规则

每个 TECH 一节，公共必输章节：`实现文件清单（|文件路径|操作-新增/修改|说明|）`、`持久层组件矩阵`、`数据流转`、`异常处理`、`测试策略`。关键方法逻辑必须写完整业务步骤/伪代码。

**API 契约写作规则**：
- **一行一字段**：禁止 `name, age, gender | 各类 | 基本信息区` 式合并行
- **禁止推回上游**：不得写「见 PRD §x.x」「与列表相同」代替字段定义
- **类型具体**：用 String/Long/DateTime/Array 等，禁止只写「各类」「Object」
- **列表与详情并存**：详情同级字段须与列表相同或更细，不可更粗
- REST 入口最小集：Method + Path + permission + 请求参数表 + 响应字段表 + 失败矩阵（含 HTTP/错误码）
- 引用的 DTO 类名必须在实现文件清单中有对应 `api/dto/*.java`

**外部映射写作规则（A-SYNC）**：
- 字段级 = 每个持久化目标列一行，禁止数组名一行带过
- 表头统一：`| 源路径 | 类型 | 目标表.字段 | 转换规则 | 空值/缺省策略 |`
- 空值/缺省策略须为 **SKIP / NULL / 默认值 / 抛错** 四选一，禁止空白

### 5. 持久层组件矩阵【强制】

`| 表名 | Entity | Repository | Mapper | 自定义Mapper#方法 | 自定义原因 |`（无自定义写「—」）

**通用持久化决策**（对齐 HZERO BaseService/BaseRepository 能力）：

| 场景 | 写法 | 禁止 |
|---|---|---|
| 主键查询 | `XxxRepository.selectByPrimaryKey(id)` | 为主键写 `<select>` |
| 非空字段等值/范围查询 | `selectOne` / `select` + 条件说明 | 单表等值/IN 写 XML |
| 按条件删除/批量删除 | `delete(condition)` | 多表 DELETE 堆同一 Mapper（应分表 Repository） |
| 单条/批量插入 | `insertSelective` / `batchInsert` | 手写 INSERT |
| 分页 + 多条件动态 WHERE | 自定义 Mapper 方法 + 完整 SQL | XML 手写分页 LIMIT（用 PageHelper） |
| 多表 JOIN / 标量子查询展示字段 | 自定义 SQL + 完整语句 | — |

**复杂 SQL 白名单（仅以下情形允许自定义 Mapper 方法 + XML + 完整 SQL，其余一律复用 BaseService/BaseRepository）**：
1. 多表 JOIN（含 inner/left/right join）
2. 复杂动态条件（if / choose / foreach / 动态 IN / 动态排序字段）
3. 聚合函数（SUM/COUNT/AVG/MAX/MIN）伴随分组、聚合筛选或聚合排序
4. 窗口函数
5. EXISTS / NOT EXISTS / 子查询 / CTE
6. 标准 BaseService/BaseRepository 条件查询无法表达且必须保留数据库侧过滤/排序/分页语义
7. 数据库层专属能力（行锁、Hint、Union、递归查询、方言特性）

**表与 Mapper 一一对应**：`XxxMapper extends BaseMapper<XxxEntity>`；禁止在非主表 Mapper 写其他表的主 SQL；禁止「子表复用主表 Mapper/Repository」。

### 6. 数据库设计硬约束【强制】

- 数据表结构清单必须含每张表**全量字段**：`| 字段名 | 字段类型 | 是否必填 | 默认 | 约束 | 索引 | 是否多语言字段 | 说明 |`
- **单表索引总数 ≤ 5**；超限必须调整查询方案或合并/删除重复及低收益索引
- **禁止物理外键及外键约束**，表间关系一律逻辑关联
- 所有逻辑关联字段（含 `xxx_id` 主数据引用）必须在「说明」列写明 `本表字段 → 目标表.目标字段`（如 `user_id → iam_user.id`）及确认来源；来源仅允许：主数据表引用、当前工程表结构/Entity/Mapper/SQL/元数据证据、用户明确指定。**冲突或无法唯一确认时进「待确认项」，禁止按字段名猜测**
- 逻辑关联须注明应用层引用存在性校验、租户/组织边界、关联数据失效处理
- 引用值集/编码规则的字段必须标注实际编码，**禁止冗余设计字段存储可关联查询出的字段**（如值已来自值集，禁止再设计名称/含义字段）
- 禁止 `SELECT *`：完整 SQL 逐一枚举字段及全部查询条件，补充排序、分页、索引、事务、行锁、超时约束

### 7. 设计点追溯矩阵【强制】

`| TECH | 形态 | 依赖 | 入口/Job | 主要类#方法 | 表/组件 | PRD 需求项 |`

- 与产品经理维护的 `traceability-matrix.md`（需求项↔原型页↔API↔代码文件↔单测）衔接：本矩阵提供 TECH→类/表 层，后者收口需求项→代码文件层
