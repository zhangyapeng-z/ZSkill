# 视觉验证参考

## 目标
在使用 Framelink Figma MCP 时建立可执行的视觉验证闭环。Framelink 主要提供 `get_figma_data` 和 `download_figma_images`，通常没有单独 screenshot 工具，因此视觉一致性需要结合 Figma selection link、资源导出、本地页面截图和人工差异清单完成。

## 视觉基准
至少保留以下证据：
- 原始 Figma selection link。
- `fileKey` 和标准化 `nodeId`。
- Framelink `get_figma_data` 摘要或保存的原始 JSON。
- 需要落地的图片/SVG 资源清单。
- 用户提供的截图；如果没有截图，则说明“未取得独立视觉截图，仅基于 Framelink data 和 Figma link 校验”。

## 实现截图
完成页面后，普通前端 Verification 不为了视觉验证启动 dev server、打开浏览器或执行截图；`截图确认`、`页面截图` 或 `browser screenshot` 只能作为外部 runtime acceptance 证据类型或用户手工验收要求，不等于允许启动服务、打开浏览器或在 Verification 内截图。只有用户当前请求明确要求打开/访问/截图某个已给定 URL/页面，且 URL/dev server、账号/租户/权限和验收范围足够明确时，才可进入独立 visual/runtime acceptance；该授权仍不得让 Verification 启动服务、打开浏览器或执行截图。用户已提供手工截图/外部浏览器证据时，只记录对应证据来源。缺证据时只记录 `screenshot=not-run`、原因和手工截图建议：
- 桌面宽度：目标 Figma frame 对应宽度，常见为 1440。
- 窄屏宽度：项目支持移动端时至少检查 375 或 390。
- 关键状态：默认态、弹窗/抽屉打开态、表格空态、表单校验态，按设计证据和任务范围选择。

## 检查项
- 布局：主要区块顺序、对齐、间距、卡片/表格/表单密度。
- 文案：确认文案是否来自 Figma 或用户输入；占位文案不能变成最终业务文案。
- 组件：按钮主次、表单控件类型、表格列结构、筛选区、工具栏、Tabs、弹窗/抽屉。
- 资源：图片/SVG 是否渲染、尺寸是否正确、是否误用业务截图。
- 响应式：文本是否溢出、按钮是否挤压、表格是否有合理滚动/列策略。
- 交互：主要按钮、弹窗开关、筛选/重置、表格行操作是否无控制台错误。

## 差异记录
交付时记录：
- 已匹配：结构、组件类型、密度、主要资源。
- 可接受差异：项目 token、组件库默认交互、浏览器字体渲染。
- 未验证差异：缺 Figma 截图、缺资源、缺真实数据、缺接口或权限。
- 阻塞差异：关键区块缺失、资源不可用、响应式破碎、组件 API 未确认。

## 不能声称完成的情况
以下情况不能说“已 1:1 还原”：
- 没有可见视觉基准，只有 Framelink data。
- 没有打开本地页面截图验证。
- 关键图片/SVG 未下载或未替代。
- 设计包含交互状态，但只实现默认静态态。
- 页面依赖接口/权限/数据状态，而这些事实尚未确认。
