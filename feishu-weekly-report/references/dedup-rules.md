# 跨源聚合去重与状态冲突处理

同一事项可能同时出现在会议纪要、任务、表格、文档、聊天记录里。周报中**同一事项只保留一条**。

## "同一事项"判定维度（满足越多越可能是同一件）

按以下维度综合判断，不只看名称：

1. 项目名称
2. 事项名称（语义相近，含别名/缩写）
3. 负责人
4. 日期（同一周期、同一截止日）
5. 内容语义（描述的是同一件事）
6. 当前状态

## 归并规则

| 场景 | 处理 |
|---|---|
| 判定为同一事项 | 保留**最新状态**一条，附上**全部主要来源链接**（会议/任务/表格各一个） |
| 多源状态一致 | 直接采用，标「已核验事实」 |
| 多源状态冲突 | **不自行选择**，标「状态冲突」，列出冲突来源，必要时给一个具体确认问题（见 status-rules.md） |
| 只在一个源出现 | 保留，来源单一，标「已核验事实」或「待确认」视证据强度 |

## 去重的保守原则

- **拿不准是否同一事项时，宁可当成两条**，分别标注，不要强行合并后丢失信息。
- 合并后必须保留"原始来源数量"的痕迹（如"来源：会议纪要 + 任务表"），供溯源。

## 冲突清单的呈现格式

在完整周报「七、待确认信息」中按如下列出：

```markdown
### 状态冲突
| 事项 | 来源A（会议纪要） | 来源B（任务表） | 需确认问题 |
|---|---|---|---|
| 非品牌售后SOP评审 | "准备启动"（8/27周会） | "已完成"（任务表） | 采用哪个状态？ |
```
