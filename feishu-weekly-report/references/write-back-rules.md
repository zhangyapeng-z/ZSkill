# 写入飞书的门槛与安全流程

## 默认：只读，不写飞书

周报默认在**对话中预览**，不写飞书、不改任何内容、不发消息。

## 触发写飞书的唯一条件

用户**明确说出**「创建飞书周报」或「写入飞书周报」等清晰指令时，才进入写流程。

## 写流程（顺序不可跳）

1. **先生成预览**（两版周报在对话中展示）。
2. **等待用户确认**（明确说"可以/确认/创建"）。
3. **创建新文档**：

```bash
lark-cli docs +create --doc-format markdown --content $'<title>工作周报 {周期}</title>\n{周报内容}'
```

4. **返回文档链接**。

## 红线

- **不得修改**原始会议纪要、任务、表格、知识库内容。
- **不得**更新任务状态、改表格、发消息、覆盖已有文档。
- 用户要求**更新已有周报**时，只能更新**用户指定的那个周报文档**，不碰其他文档：

```bash
lark-cli docs +update --doc "<用户指定文档url_or_token>" --command append --doc-format markdown --content $'{内容}'
```

- 写操作前可先 `--dry-run` 预览；遇高风写风险（exit code 10）先展示待执行动作、获确认后再带 `--yes` 重跑，**绝不自行追加 `--yes`**。
