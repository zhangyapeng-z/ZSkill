# 评估用例库（Evals）

本目录包含对抗性审查 skill 的测试用例，用于回归测试和质量追踪。每次修改 SKILL.md 或专家池文件后，应运行这些用例验证质量没有退化。

---

## 一、评估方法

### 1.1 评估流程

1. **准备**：从 fixtures/ 中选取测试用例
2. **执行**：使用对抗性审查 skill 对测试用例进行审查
3. **核对**：对照下方的「预期检查点」逐项验证
4. **记录**：记录通过/不通过的项目，以及意外发现的问题
5. **迭代**：归纳失败模式，修改 SKILL.md，重新验证

### 1.2 评分维度

| 维度 | 权重 | 说明 |
|---|---|---|
| 关键问题捕获率 | 40% | 预期的 P0/P1 问题是否被发现 |
| 严重度准确性 | 20% | 严重度分级是否合理（没有夸大也没有缩小） |
| 流程完整性 | 15% | 八步工作流是否完整执行，有无跳步 |
| 输出格式合规性 | 10% | 是否符合 output-template.md 规范 |
| 无幻觉率 | 10% | 是否存在虚构内容 |
| 大白话可读性 | 5% | 非专业人士能否看懂 |

### 1.3 通过标准

- **关键问题捕获率 ≥ 80%**（核心 P0/P1 问题不能漏）
- **严重度准确性 ≥ 70%**
- **流程完整性 = 100%**（不能跳步）
- **无幻觉率 = 100%**（不能有虚构内容）
- **输出格式合规性 ≥ 90%**

## 五、新增测试用例指南

新增测试用例时，请遵循以下原则：

1. **覆盖典型场景**：每个用例聚焦一类常见问题
2. **包含已知缺陷**：用例中应预埋已知的问题，用于验证 skill 能否发现
3. **控制复杂度**：极速模式用例要简单，深度模式用例要复杂
4. **混合类型优先**：尽量包含混合类型场景，测试类型识别和专家补位
5. **边界场景**：包含信息不足、有歧义等边界情况
