# 维护指南（Contributing）

本文件说明对抗性审查 skill 的维护规则和扩展指南。

---

## 一、规则归属表

各类规则维护在以下文件中，修改时请同步更新对应位置，避免规则漂移：

| 规则类别 | 维护文件 | 说明 |
|---|---|---|
| 工作流与总流程 | `SKILL.md` | 八步工作流、模式、触发与边界 |
| 约束与铁律 | `references/constraints.md` | 六类硬性约束 |
| 心智模型 | `references/mental-models.md` | 底层逻辑与设计理念 |
| 输入/输出契约 | `references/io-contract.md` | 结构化接口定义（MCP 用） |
| 专家角色框架 | `references/expert-framework.md` | 五要素、意见格式、动态定制、选配规则 |
| 方案/决策类专家池 | `references/reviewers/plan-decision.md` | 6 位专家定义 + 选配规则 |
| 代码/技术类专家池 | `references/reviewers/code-tech.md` | 7 位专家定义 + 修复审查规则 |
| 文档/内容类专家池 | `references/reviewers/document-content.md` | 5 位专家定义 + 选配规则 |
| 输出报告格式 | `references/output-template.md` | 报告结构、问题格式、修订版规范 |

| 评估用例 | `evals/evals.md` | 测试用例清单与评估方法 |
| 用户指南 | `README.md` | 面向人类用户的使用说明 |

---

## 二、新增审查类型

新增审查类型（如法律审查、财务审查、设计审查等）时，按以下步骤操作：

1. **新增专家池文件**：`references/reviewers/<类型>.md`
   - 遵循 expert-framework.md 的五要素模板
   - 包含 3-7 位专家定义
   - 包含选配规则（极速/标准/深度各选谁）
   - 包含混合类型处理说明

2. **更新路由表**：在 `SKILL.md` 第九节（类型识别路由）中增加条目

3. **新增测试用例**：在 `evals/fixtures/` 中新增 2-3 个测试用例，并在 `evals/evals.md` 中登记

4. **更新文档**：更新 `README.md` 中的「能审什么」部分

---

## 三、新增专家

在已有类型中新增专家时：

1. 在对应专家池文件中添加专家定义（五要素完整）
2. 更新选配规则：说明什么场景下会选这位专家
3. 检查是否影响默认组合（极速/标准/深度的默认专家列表）
4. 用现有测试用例回归测试，确保新增专家不破坏现有流程

---

## 四、修改流程

修改 SKILL.md 或核心规则时，请遵循以下流程：

1. **明确修改目标**：要解决什么问题？是修复 bug 还是新增功能？
2. **定位要改的文件**：参考规则归属表，避免多处定义导致漂移
3. **执行修改**：修改对应文件
4. **回归测试**：用 evals/ 中的测试用例验证，确保质量不退化
5. **记录变更**：在版本历史中记录修改内容和原因
